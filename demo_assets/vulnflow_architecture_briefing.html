Problem statement

The gap VulnFlow is built to close.

THE PROBLEM
Scanners tell teams what is vulnerable, but turning findings into safe, policy-compliant, verified fixes is still manual, slow and risky at scale.
Who feels it
  • • Developers lose time to triage and upgrades
  • • Security cannot see which findings share a fix
  • • Leaders see backlogs, not closure
Why current tools fall short
  • • Scanners stop at detection
  • • Bump bots lack root-cause and policy context
  • • Fixes are rarely tested and rescanned first
What a solution must do
  • • Group findings by root cause
  • • Enforce policy in code
  • • Test in a sandbox, verify by rescan
  • • Keep humans on risky changes

Agentic AI: specialized agents, bounded roles

Each agent has one job, its own tools, and a hard limit on what it can decide.

Triage agent
Sorts deduplicated findings so the right ones reach planning.
Fast model here; a stronger one plans.
Root-cause agent
Traces transitive CVEs to the direct parent using the Neo4j graph.
Cannot override graph facts.
Planner agent
Proposes a target version and cites the advisories behind it.
The policy engine can reject the plan.
Self-correcting fixer
Reads build and test failures, rolls back and tries a safer version.
Works only inside the sandbox.
Verifier agent
Rescans and compares before and after.
Never reports a failed scan as success.
Secrets & expiry agents
Draft rotation checklists for leaked secrets and flag expiring certs.
Sees fingerprints and line numbers, never secret values.
Goal-driven • Tool-using via MCP • Stateful and resumable • Self-correcting • Bounded autonomy

Governance: policy in code, humans at the gates

Rules load from YAML, Artifactory, Nexus or OPA. The model never makes the call.

Risk model enforced in code
AUTO
Minor and patch bumps that pass sandbox tests open a PR.
REVIEW
Major upgrades and unknown packages pause the run (exit 10).
BLOCKED
Banned packages open a Jira exception ticket (exit 20).
Approval workflow
BUILT
Approval state persisted in Supabase, so decisions survive across runs
